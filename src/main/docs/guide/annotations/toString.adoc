If you annotate a Java Bean with `@ToString`, a `[Bean]Object` class is generated at compilation-time
with a static implementation of the java.utils.Object's toString() method.

- Properties that do not wish to be printed out should be annotated with @ToString.Exclude
- All bean properties (with getters) will be written in the form of a Java Record in the generated toString() method with signature:

    `public static String [BeanName]Object.toString(BeanName object)`

NOTE: The user is expected to use the generated static method by overriding the toString() method themselves.

[.lang-groovy]
NOTE: A Groovy class cannot call the class generated from itself (`ElephantObject`) because the generated source is not resolvable in the same Groovy compilation, so the `toString()`, `equals()` and `hashCode()` overrides of this example are only shown for Java, Kotlin and Python.

[.lang-python]
NOTE: A Python class overrides `+__str__+`, `+__eq__+` and `+__hash__+` instead and loads the generated class with `java.type(...)`, because the generated type has no Python module yet. The nested `ToString.Exclude` and `EqualsAndHashCode.Exclude` annotations are imported under `if TYPE_CHECKING:` because the generated `ToString` module does not expose them at runtime.
